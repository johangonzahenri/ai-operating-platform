## 1. Executive Summary

Milestone **v0.9 — Bounded Autonomous Operations** delivers goal-oriented, multi-step autonomous execution capabilities to the AI Operating Platform without compromising governance, determinism, or system stability.

Unconstrained autonomy presents severe enterprise risks: runaway token billing, infinite loops, bypassed security policies, and unmonitored background daemons. Milestone v0.9 eliminates these risks through the architectural contract of **Bounded Autonomy**:
- Every autonomous operation is constrained by an immutable **`AutonomyBudget`** (`maxSteps`, `maxDurationMs`, `maxToolCalls`, `maxTokens`).
- The execution cycle is strictly finite: loops are mathematically bounded by `budget.maxSteps`.
- Execution ownership remains 100% centralized within **`CoreRuntime`** (`AutonomousOrchestrator -> Task -> CoreRuntime -> Execution`).
- Every planned step passes through **`PolicyGateway`**; if denied or if policy evaluation throws, the operation halts immediately (*fail-closed*).
- Operations are exposed via the **Platform REST API** and managed interactively through the **Web Control Plane** (SPA), engineered exclusively with native DOM APIs (zero `innerHTML`).
- Zero external production dependencies (`npm ls --omit=dev` is strictly empty).

## 3. Architecture & Delivered Components

### 3.1 Domain Layer (`src/domain/autonomy/`)
- **`AutonomyBudget`**: Immutable Value Object enforcing positive bounds on `maxSteps`, `maxDurationMs`, `maxToolCalls`, and optional `maxTokens`.
- **`AutonomyConsumption`**: Value Object recording copy-on-write operational metrics (`stepsUsed`, `elapsedMs`, `toolCallsUsed`, `tokensUsed`).
- **`AutonomousOperation`**: Pure domain entity governing the lifecycle finite state machine:
  $$\text{SUBMITTED} \longrightarrow \text{RUNNING} \longrightarrow \{\text{COMPLETED}, \text{FAILED}, \text{CANCELLED}, \text{BUDGET\_EXHAUSTED}\}$$
- **`PlanningRequest`, `Plan`, `PlanStep`**: Declarative planning contracts strictly rejecting executable code or functions.
- **`Decision`**: Immutable operational determination (`EXECUTE_STEP`, `COMPLETE`, `STOP`, `FAIL`).
- **`Observation`**: Serializable value object capturing step execution outcomes, error classification, and tool metrics.
- **`ObjectiveEvaluation`**: Contract decoupling execution success from goal satisfaction (`ACHIEVED`, `NOT_ACHIEVED`, `UNKNOWN`).
- **`PlannerPort`**: Vendor-agnostic domain port for plan generation.
- **`DecisionEvaluatorPort`**: Pure domain port for deterministic decision derivation.
- **`OperationRepositoryPort`**: Domain repository interface for aggregate persistence and retrieval.

### 3.2 Application Layer (`src/application/autonomy/`)
- **`AutonomousOrchestrator`**: Application service coordinating the bounded operational loop:
  1. Validates preconditions and cancellation tokens.
  2. Generates plan via `PlannerPort`.
  3. Executes finite `for` loop (bounded strictly by `budget.maxSteps`).
  4. Enforces fail-closed `PolicyGateway` evaluation per step.
  5. Submits atomic `Task` to `CoreRuntime.execute()`.
  6. Maps execution result to `Observation` and updates consumption.
  7. Derives next `Decision` via `DecisionEvaluatorPort`.
- **`AutonomousOperationService`**: Mediates between external API requests and `AutonomousOrchestrator`, managing agent validation, domain entity lifecycle, and cooperative cancellation tokens.

### 3.3 Infrastructure Layer (`src/infrastructure/`)
- **`InMemoryOperationRepository`**: Persists operations in memory with copy-on-write defensive cloning and frozen read projections (`OperationProjection`, `OperationDetailProjection`).
- **`StubPlanner`**: Deterministic default planning adapter.
- **`DeterministicDecisionEvaluator`**: Pure, side-effect-free decision engine implementing 7 deterministic evaluation rules.

### 3.4 Platform API Layer (`src/platform/api/`)
- **Endpoints** (available under `/api/v1/` and backward-compatible `/api/`):
  - `GET /api/v1/operations`: List all operations with summary projections.
  - `GET /api/v1/operations/:id`: Get full operation detail snapshot.
  - `POST /api/v1/operations`: Validate, create, and synchronously run a bounded operation.
  - `POST /api/v1/operations/:id/cancel`: Cancel an active or pending operation.
- **Security Controls**: Path traversal blocked (`403`), CORS restricted to localhost, payload capped at 1MB (`413`), strict `application/json` enforcement (`415`), normalized alphanumeric IDs.

### 3.5 Web Platform Control Plane (`src/platform/web/`)
- **Autonomous Operations Tab**: Dedicated operator view for submitting operations with configurable budget limits.
- **Operations Table**: Reactive tabular view with status badges, budget consumption progress, and cancel/inspect actions.
- **Operation Inspector**: Detailed view displaying budget vs. consumption gauges, plan timeline, observation logs, and decision rationale audit.
- **XSS Prevention**: 100% pure DOM APIs (`createElement`, `textContent`, `setAttribute`). Strictly zero `innerHTML`.

## 5. Known Limitations & Deferred Scope

### 5.1 Known Limitations (v0.9)
1. **In-Memory Volatility**: `InMemoryOperationRepository` stores records in process memory. Platform restarts clear historical operations. (By design for v0.9; durable storage is scheduled for v0.10).
2. **Synchronous HTTP Execution**: Operations triggered via `POST /api/v1/operations` execute synchronously within the HTTP request lifecycle, constrained by `maxDurationMs`. Client connections remain open during execution.
3. **Inter-Step Cancellation**: Cancellation tokens are evaluated before each discrete step. In-flight task cancellation (aborting an active external network socket or model inference mid-stream) is an open architectural design (OAD-001) scheduled for future refinement with `AbortSignal`.

### 5.2 Deferred to v0.10 & v1.0
- **v0.10 — Durable Persistence**: Decoupled database adapters (e.g., PostgreSQL/SQLite) implementing `OperationRepositoryPort` and `TaskRepositoryPort`.
- **v1.0 — Distributed Multi-Node & Queuing**: Asynchronous background dispatch, distributed job queues, worker pools, and horizontal scaling.
- **Model Provider SDKs**: Concrete cloud LLM integrations (Gemini, Claude, OpenAI) via `ModelGateway` adapters.
