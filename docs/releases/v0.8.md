## 1. Executive Summary

Milestone **v0.8 — Agents** elevates the AI Operating Platform from low-level model and sequential tool orchestration into a **governed, stateful, and observable Agent execution environment**.

All agent operations are executed strictly through the foundational `CoreRuntime`, preserving all core invariants established across v0.1–v0.7:
- Deterministic state machines for `Task` and `Execution`.
- Fail-closed policy governance.
- Synchronous event recording with correlation (`traceId`, `taskId`, `executionId`, `agentId`).
- Scoped and isolated memory partitions.
- Zero runtime npm dependencies.

## 2. Delivered Architecture & Components

### 2.1 Domain Layer (`src/domain/agent/`)
- **`Agent`**: Rich domain entity with lifecycle status (`ACTIVE`, `INACTIVE`), immutable snapshot generation (`toSnapshot()`), frozen tool access lists, deterministic memory scoping defaulting to `agent-${id}`, and property update tracking.
- **`AgentRegistry`**: Port defining contract for storing, querying, and verifying agents with conflict detection and idempotency.

### 2.2 Application & Runtime Layer (`src/application/`)
- **`AgentExecutionStrategy`**: Single execution pipeline implementing `ExecutionStrategy`. Resolves agent configuration, retrieves scoped memory context, enforces fail-closed policy checks before tool invocation, publishes correlated lifecycle events (`agent.started`, `agent.completed`, `agent.failed`), and executes registered tools through `ToolGateway`.
- **`AgentService`**: Orchestrates application use cases (`createAgent`, `getAgent`, `listAgents`, `updateAgent`, `executeAgentTask`) over domain boundaries without leaking infrastructure.
- **`SubmitTask` / `ExecuteOrchestration`**: Fully integrated with CoreRuntime and governed strategies.

### 2.3 Infrastructure Layer (`src/infrastructure/agent/`)
- **`InMemoryAgentRegistry`**: Thread-safe (in-memory async) adapter fulfilling `AgentRegistryPort` with unique ID and name validation.

### 2.4 Platform API Layer (`src/platform/api/`)
- **REST Endpoints**:
  - `POST /api/v1/agents`: Register new agent definitions.
  - `GET /api/v1/agents`: Query registered agents.
  - `GET /api/v1/agents/:id`: Query single agent details.
  - `PUT /api/v1/agents/:id`: Update agent mutable properties.
  - `POST /api/v1/agents/:id/tasks`: Submit and synchronously dispatch task execution through `CoreRuntime`.
- **Security & Hygiene**: Loopback-only binding (`127.0.0.1`), restrictive CORS headers, input sanitization, and structured HTTP error formatting.

### 2.5 Web Platform Control Plane (`src/platform/web/`)
- **SPA UI**: Dedicated Agents panel with interactive Agent creation, listing, status toggling, and live task dispatching.
- **Hygiene & Security**: Zero `innerHTML` usage (100% strictly typed DOM APIs via `document.createElement`), isolated client networking via `api-client.js`.

## 3. Deliberately Excluded Scope (Deferred to v0.9+)

The following capabilities were **strictly omitted** from v0.8 to maintain bounded, deterministic control:
1. **Autonomous Execution Loops (`while(true)`):** Agents in v0.8 only run bounded, single-pass executions triggered via explicit tasks.
2. **Dynamic Sub-Task Decomposition / Planners:** Agents cannot decompose tasks into unconstrained sub-agents without human approval.
3. **Background Daemon Schedulers:** No unmonitored background workers or cron loops exist in the engine runtime.
4. **Direct External Model Calls:** No bypass of `ModelGateway` or `ToolGateway`.
5. **Self-Modifying System Prompts:** Agents cannot mutate their own operational constraints or allowed tool scopes at runtime.
